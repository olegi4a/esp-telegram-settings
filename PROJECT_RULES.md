# ПРАВИЛА РОБОТИ З ПРОЄКТОМ (Версія 3.7.0)

## 🔐 БЕЗПЕКА ТА GITHUB
1. **КРИТИЧНО:** Файл `CREDENTIALS.md` (з токенами та паролями) **НІКОЛИ** не має потрапляти на GitHub. Він доданий у `.gitignore`.
2. **ОФІЦІЙНИЙ РЕПОЗИТОРІЙ:** Увесь інший код проекту (`src`, `lib`, `data`, `CHANGELOG.md`) синхронізується з GitHub для забезпечення історії версій та роботи OTA-оновлень.
3. **OTA ОНОВЛЕННЯ:** Пристрій завантажує файли з гілки `main`. Після кожного релізу обов'язково робити `git push` та оновлювати теги.

## 🛠 WORKFLOW: ЗБІРКА ТА РЕЛІЗ
1. **УНІВЕРСАЛЬНІСТЬ:** Ми використовуємо один бінарний файл для всіх типів дисплеїв.
2. **ОСНОВНЕ ОТОЧЕННЯ:** Для фінальної збірки релізу використовувати `env:oled_128x64` у PlatformIO. Ця збірка є універсальною завдяки рантайм-логіці `display_type`.
3. **ПОРЯДОК РЕЛІЗУ:**
   - Оновити версію в `src/set.h`.
   - Оновити `CHANGELOG.md`.
   - Зібрати прошивку (`pio run -e oled_128x64`).
   - Створити папку в `releases/` та скопіювати туди `firmware.bin` та файли з `data/`.
   - Запушити зміни та створити тег на GitHub.
   - Завантажити активи (assets) у реліз через GitHub API або Web UI.

## 📝 СТАНДАРТИ КОДУ
- Використовувати `TBLOG` для налагодження.
- Не використовувати статичні макроси `#ifdef` для вибору дисплея; замість цього використовувати глобальну змінну `display_type`.
- При зміні критичних налаштувань (тип дисплея, Wi-Fi) обов'язково вимагати перезавантаження пристрою.
