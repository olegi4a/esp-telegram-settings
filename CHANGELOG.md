# EDwiC ESP Telegram BOT - Опис та Журнал змін

## Опис роботи пристрою

Цей пристрій на базі мікроконтролера ESP8266 призначений для розумного моніторингу та керування навантаженням (через реле) за допомогою сенсорів (температури, вологості), таймерів та віддаленого контролю.

### Основний функціонал:
1. **Інтерфейси керування**: 
   - **Telegram-бот**: Дозволяє віддалено моніторити стан (температура, вологість, реле), отримувати сповіщення про тривоги, зникнення живлення та керувати налаштуваннями через MiniApp.
   - **Локальний Web-інтерфейс**: Повноцінний сучасний дашборд для налаштування всіх параметрів пристрою в локальній мережі (через IP-адресу).
   
2. **Система профілів (Режими роботи)**:
   Пристрій має гнучку систему налаштувань, яка розподілена на профілі:
   - **Робота за розкладом (Вимкнена)**: Використовується єдиний **"Загальний профіль"** цілодобово.
   - **Робота за розкладом (Увімкнена)**: Система автоматично перемикається між **"Денним"** та **"Нічним"** профілями в залежності від заданого часу (наприклад, з 08:00 до 20:00 - День, решта часу - Ніч).
   
3. **Режими керування реле (в межах профілю)**:
   - **Ручне керування**: Навантаження вмикається/вимикається виключно користувачем.
   - **Автоматика за датчиком (Термостат)**: Реле вмикається/вимикається на основі заданої температури (Уставка) з урахуванням гістерезису.
   - **Автоматика за таймером**: Циклічне вмикання/вимикання реле за вказаними проміжками часу (Час ON / Час OFF).

4. **Система тривог та безпеки**:
   - Сповіщення при виході температури за критичні межі (Max / Min).
   - Сповіщення про перезавантаження та втрату основного живлення 220В.
   - Можливість визначити початковий стан реле після знеструмлення пристрою.

## Журнал змін (Changelog)

Тут фіксуються всі успішні оновлення, рефакторинги та виправлення багів.

### [17-04-2026] - Рефакторинг Web UI та системи профілів
- **Web UI (Dirty State Manager)**: Виправлено систему відстеження змін у формах ("Dirty State"). Тепер система безпомилково розпізнає незбережені зміни в налаштуваннях.
- **Web UI (Telegram Token & Passwords)**: Усунено баг некоректного порівняння токенів та паролів (прибрано функцію `parseFloat`, яка ігнорувала літери), тепер вони правильно підсвічуються та блокують навігацію.
- **Web UI (Кнопки режимів)**: Перемикачі "Режим роботи" та "Реле при старті" тепер правильно підсвічуються (впроваджено клас `.dirty-wrap` для `DIV` елементів) та реагують на кліки.
- **Web UI (Логіка збереження системи)**: Оптимізовано збереження на вкладці "Система". Тепер після збереження форма дійсно оновлює еталонні дані та знімає помаранчеві рамки попереджень без необхідності перезавантаження сторінки.
- **Web UI (Блокування навігації профілів)**: 
  - Реалізовано вибіркове блокування перемикання між профілями (День/Ніч): перехід блокується, тільки якщо є незбережені зміни безпосередньо в самих параметрах профілю.
  - Кнопка "Робота за розкладом" заблокована для перемикання, якщо є незбережені зміни в активному профілі (захист від втрати налаштувань).
- **Пам'ять (RAM / Heap)**: Усунено витік пам'яті (memory leak) при відправці JSON з ендпоінтів `/api/config` та `/api/status`. Замінено проміжні `String` буфери на прямий стрімінг у TCP сокет (`WiFiClient`), що звільнило ~5 KB Heap і стабілізувало роботу сенсорів (особливо OneWire DS18B20).
- **Firmware (Автоматика часу)**: **КРИТИЧНО!** Виявлено та виправлено баг, через який змінна поточного часу `Time_now` ніколи не оновлювалася (завжди дорівнювала 0). Це призводило до того, що автоматичне перемикання День/Ніч не працювало (завжди був активним Нічний профіль). Тепер час розраховується правильно на старті та в основному циклі `loop()`.
